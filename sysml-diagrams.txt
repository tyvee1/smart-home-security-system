note right of CloudServices
  Aggregation, not composition.
  SHSS-F-026 requires the system to
  detect, record, sound and log with
  the relay unreachable, so the system
  does not own this part's lifetime.
end note

note bottom of PoENetworkSwitch
  Declared as its own block because it
  converts 12 V to 48 V. An undeclared
  converter is how an ICD ends up with a
  12 V source feeding a 48 V part.

note as NOTE1
  Three relationship types, three different meanings:
  «deriveReqt»  this requirement exists because of that one
  «satisfy»     this design element is allocated the requirement
  «verify»      this test case produces the evidence
  A requirement with a satisfy and no verify has an owner
  and no evidence. That is the gap this diagram exists to show.
end note
@enduml

' 3. State machine — arming states
' ---------------------------------------------------------------------
@startuml sysml-state-machine
title stm [block] ControlUnit [Arming states]
skinparam backgroundColor #FFFFFF
skinparam shadowing false
skinparam state {
  BackgroundColor #FFFFFF
  BorderColor #5B626E
  ArrowColor #5B626E
  FontName Helvetica
  FontSize 12
}

[*] --> Disarmed

state Disarmed : sensors report and log
state Disarmed : no intrusion alarm
state Disarmed : leak and tamper alarms stay active

state Arming : exit delay 30-120 s, default 60
state Arming : open perimeter zones announced

state "Armed Stay" as Stay : perimeter active
state "Armed Stay" as Stay : interior motion bypassed

state "Armed Away" as Away : all intrusion zones active

state "Entry Delay" as Entry : 15-60 s, default 30
state "Entry Delay" as Entry : delayed zone opened

state Alarm #FDECEB : annunciators sound
state Alarm #FDECEB : triggering camera records
state Alarm #FDECEB : notifications sent
state Alarm #FDECEB : monitoring signalled after the abort window

state Maintenance : alarm outputs inhibited
state Maintenance : owner notified on entry and exit
state Maintenance : 4 hour session limit

Disarmed --> Arming : arm(Stay | Away)
Arming --> Stay : exitDelayExpired [Stay selected]
Arming --> Away : exitDelayExpired [Away selected]
Arming --> Disarmed : validDisarm

Stay --> Entry : delayedZoneOpened
Away --> Entry : delayedZoneOpened
Stay --> Alarm : instantZoneViolated
Away --> Alarm : instantZoneViolated
Stay --> Disarmed : validDisarm
Away --> Disarmed : validDisarm

Entry --> Disarmed : validDisarm
Entry --> Alarm : entryDelayExpired

Alarm --> Disarmed : validDisarm / cancel monitoring if within abort window

Disarmed --> Maintenance : maintainerSession [owner consent]
Maintenance --> Disarmed : sessionEnded | 4h limit

Disarmed --> Alarm : waterLeakDetected | tamperDetected
Stay --> Alarm : duressCodeEntered
Away --> Alarm : duressCodeEntered

note right of Alarm
  Degraded is orthogonal to these states,
  not one of them: the system can be
  Degraded while Armed Away. Degraded
  never suppresses a transition into Alarm.
  Modelling it as a sibling state would make
  an outage look like an arming mode.
end note
@enduml


' ---------------------------------------------------------------------
' 4. Sequence diagram — an intrusion, end to end
' ---------------------------------------------------------------------
@startuml sysml-sequence
title sd [interaction] Intrusion detected while Armed Away
skinparam backgroundColor #FFFFFF
skinparam shadowing false
skinparam sequence {
  ArrowColor #5B626E
  LifeLineBorderColor #8A919C
  ParticipantBorderColor #5B626E
  ParticipantBackgroundColor #FFFFFF
  ActorBorderColor #5B626E
  FontName Helvetica
  FontSize 11
}

actor Intruder
participant "Door/Window\nSensor" as DW
participant "Control Unit" as CU
participant "Camera" as CAM
participant "Alarm\nAnnunciator" as AL
participant "Cloud Relay" as CR
actor "Homeowner" as HO
participant "Monitoring\nService" as MS

note over CU : state = Armed Away

Intruder -> DW : forces rear door
DW -> CU : sensorEvent(zone=R2, open)\n<< Z-Wave, AES-128 >>
note right of CU : SHSS-F-005 — within 2 s

alt zone is instant
  CU -> CU : setState(Alarm)
else zone is delayed
  CU -> CU : setState(Entry Delay)
  note right of CU : 30 s to disarm
  CU -> CU : entryDelayExpired → setState(Alarm)
end

CU -> CAM : record(trigger=R2, preRoll=10 s)
activate CAM
CAM --> CU : clipHandle
note right of CAM : SHSS-F-011 — recording\nstarts within 1 s and\nincludes the 10 s before
deactivate CAM

CU -> AL : sound()
activate AL
AL --> CU : ack
note right of AL : SHSS-F-015 — 85 dBA at 3 m\nwithin 1 s. Local, so it fires\nwhether or not CR is reachable.
deactivate AL

CU -> CU : appendEventLog(identity, zone, time)

group Cloud Relay reachable
  CU -> CR : event(zone=R2, type=intrusion, t)
  CR -> HO : push notification
  note right of HO : SHSS-P-001 — 10 s end to end,\n95th percentile
  CU -> CR : upload(alarm clip)
end

group Cloud Relay unreachable  [SHSS-F-026, SHSS-F-035]
  CU -> CU : queue event locally, up to 7 days
  CU -> MS : SIA DC-09 over LTE failover
  note right of CU : Alarm still sounded.\nRecording still made.\nLog still written.\nOnly remote delivery is delayed.
end

opt abort window has not expired
  HO -> CU : disarm(credential)
  CU -> AL : silence()
  CU -> MS : cancel signal
  note right of CU : SHSS-F-019 — 15 to 60 s,\ndefault 30. Most alarms are\nthe owner's own mistake.
end

opt duress code used
  HO -> CU : disarm(duressCode)
  CU -> AL : silence()
  CU -> MS : silent alarm, dispatch
  note right of CU : SHSS-F-018 and SHSS-O-003 —\nno visual, audible or haptic\ndifference from a normal disarm.
end
@enduml
